# Sprite Editor

Sprite Fusion의 캔버스 중심 흐름을 참고한 로컬 픽셀 편집기입니다.
sprite-gen 생성, Pixel Snapper 정규화, 비파괴 자산 버전, 프레임 타임라인,
맵 배치와 프로젝트 export를 하나의 작업 공간으로 연결합니다.

## 실행

Node.js 22+, Python 3.10+, macOS/Linux가 필요합니다.

```sh
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

# 터미널 1
npm run api
# 터미널 2
npm run dev
```

브라우저에서 http://127.0.0.1:5186 을 엽니다. API는 127.0.0.1:8796에만 바인딩됩니다.
다른 프로세스가 포트를 사용하면 오류를 확인하고 중복 서비스를 종료하거나 설정을 조정합니다.
외부 네트워크에 서버를 노출하지 마세요. 공개 다중 사용자 서비스가 아닌 로컬 앱입니다.

## 생성 연결

[sprite-gen](https://github.com/aldegad/sprite-gen)을 별도로 설치합니다.
PATH의 `sprite-gen` 또는 기본 Codex 스킬 설치 위치의 CLI를 찾습니다.
다른 위치라면 API 실행 전에 절대 경로를 지정합니다.

```sh
export SPRITE_GEN_BIN=/absolute/path/to/sprite-gen/.venv/bin/sprite-gen
npm run api
```

원하는 provider를 선택하고 Generate를 누르면 그 계정의 한도·과금 정책으로
실제 생성이 실행됩니다. 선택한 자산을 참조해 편집·변형할 수 있습니다.
목표 크기는 생성 요청이며, 실제 출력 크기를 강제로 찌그러뜨리지 않습니다.
권한·크레딧 확인을 CLI 존재 여부로 대신하지 않습니다. 실패 시 자동 재결제/재시도하지 않습니다.

작업 취소는 로컬 실행을 종료하고 결과의 자산 등록을 막습니다. 종료 신호에 응답하지
않으면 5초 유예 후 실행 그룹을 강제 종료합니다. 외부 제공자에서 이미 시작한 생성이나
과금까지 취소한다는 의미는 아닙니다. API의 정상 종료(SIGTERM/Ctrl+C)도 진행·대기 작업을
취소하며, 중복 서버 실행은 기존 작업의 상태를 변경하지 않습니다.

## 애니메이션 생성

저장된 기준 자산을 선택하고 Create의 **애니메이션** 모드로 전환합니다.
동작 설명, 상태(idle/walk/run/attack/jump), 2~16프레임, FPS, 반복 여부를 설정합니다.
GPT 이미지 생성 이용 권한을 확인한 뒤 Animate를 누르면 실제 계정으로 실행됩니다.
이 모드는 GPT 이미지 행 방식이며, 기준 이미지의 방향을 유지하는 한 상태를 생성합니다.
새 방향 기준 생성은 아래의 별도 모드에서 먼저 실행합니다. Grok 영상 애니메이션은 아직 연결하지 않았습니다.

`workflow → prepare → gen-set → extract → compose-atlas → inspect`를 순서대로 실행합니다.
원본은 바꾸지 않고 작업별 새 run 디렉터리를 사용합니다. 준비·생성·추출 등의 진행 단계가
작업 내역에 표시됩니다. 전체 단계는 하나의 20분 실행 제한을 공유하며 자동 재시도하지 않습니다.
중간 실패·취소·잘못된 출력 수·검사 실패가 있으면 클립을 등록하지 않습니다.

성공한 작업에서 **생성 클립 추가 / 열기**를 눌러 프로젝트에 추가합니다. 같은 결과를
반복 클릭해도 복제하지 않으며 기존 클립은 유지됩니다. 프레임 수·픽셀 구조 검사 통과가
자연스러운 움직임이나 정체성 보존을 보증하지 않으므로 재생하며 확인하세요.
검증은 로컬 실행 파일 및 알려진 격자 fixture로 수행했고 실제 유료 생성은 미실행입니다.

새 애니메이션 작업은 **Pixel Unfake / 정규화 전** 두 클립을 반환합니다. 정규화 전 버전은
sprite-gen이 추출한 셀 크기 plain 프레임이며, 재생성하거나 누락된 원본을 픽셀 결과로
대체하지 않습니다. 두 클립의 순서와 시간은 같습니다. 원본 쌍이 없으면 작업이 실패합니다.
상위 버전이 있는 자산은 Sprite 캔버스의 **비교**로 나란히 보고 선택할 수 있습니다.
저장 중인 픽셀 수정이 있으면 먼저 수정본을 저장해야 비교할 수 있습니다.

## 방향 기준 생성

Create의 **방향 기준**에서 앞/뒤/좌/우와 네 대각선 중 1~8개를 고릅니다.
GPT 이용 권한을 확인하고 실행하면 방향별 1프레임 기준을 생성합니다. 좌우 반전으로
대체하지 않으며 선택한 방향마다 생성 요청과 계정 사용량이 발생합니다.
결과는 작업 내역에 방향별로 표시됩니다. 얼굴·장비·비대칭 장식을 직접 확인한 뒤
**기준 선택**을 누르면 해당 저장 자산을 사용하는 애니메이션 모드로 이동합니다.

한 작업의 모든 방향·크기·프레임 수·검사가 맞아야 결과를 등록합니다. 현재는 방향 기준을
각각 선택해 애니메이션을 생성하는 흐름이며, 확인된 모든 방향의 모션 일괄 실행은 별도 후속 작업입니다.
실제 제공자 결과의 방향 정확도는 아직 검증하지 않았습니다.

## Pixel Snapper

Rust를 설치한 뒤 고정된 upstream 소스를 빌드합니다.

```sh
cargo build --locked --release --manifest-path vendor/pixel-snapper/Cargo.toml
```

기존 설치를 쓰려면 `PIXEL_SNAPPER_BIN=/absolute/path/to/spritefusion-pixel-snapper`를
설정합니다. 한글 경로에서 Rust 빌드가 실패하면 ASCII 이름의 디렉터리에서 빌드하거나
ASCII 경로 별칭을 사용하세요. Python 서비스는 완성된 바이너리를 자동으로 찾습니다.
정규화는 입력을 보존하고 새 자산으로 저장합니다. 자동 스냅은 고정 32×32 resize가 아닙니다.

## 편집과 저장

- `+`: 32×32 빈 스프라이트. PNG Import: 최대 12MB, 각 변 2048px.
- Sprite: 브러시·지우개·스포이트·격자·줌·undo/redo. **수정본 저장**은 새 revision입니다.
- Timeline: 이름별 클립, 프레임 추가·순서 이동·제거, 프레임별 시간(ms), 반복/한 번 재생,
  atlas PNG+JSON export. FPS를 바꾸면 해당 클립의 시간을 균등하게 설정합니다.
- 프레임의 보관 버튼은 재생에서 제외하고 후보 목록에 원래 시간으로 보관합니다.
  후보의 위쪽 화살표로 재생 목록 끝에 복원할 수 있습니다. 후보는 재생·아틀라스 출력에는
  포함하지 않지만 프로젝트 저장·복원에 포함됩니다. 재생/후보는 각각 클립당 최대 256개입니다.
- Map: 선택 자산을 격자 기준 배치, 지우기, 연결 영역 채우기, 레이어 표시·충돌,
  undo/redo, PNG export. 채우기는 선택 레이어의 상하좌우로 연결된 같은 자산 또는
  빈 영역에만 적용되며 다른 레이어와 경계를 보존합니다. 채우기 전체는 한 번에 되돌립니다.
- Export project: 자산 PNG를 포함하는 `.sprite.json`. 프로젝트 열기로 다른 설치에도 복원.
- 프로젝트 구성은 브라우저에 자동 저장됩니다. 픽셀 수정은 **수정본 저장**을 눌러 반영합니다.
- `.data/`는 자산, SQLite, 작업 기록을 보관합니다. Git에 포함되지 않습니다.
  브라우저 저장소와 `.data/`는 별개이므로 이동/백업에는 Export project를 사용하세요.

## sprite-gen 아틀라스 가져오기

Sprite 화면의 **sprite-gen 가져오기**에서 완성된 작업의 `manifest.json`과
`sprite-sheet-alpha.png`를 선택합니다. `frame_layout.rows`의 실제 사각형으로 프레임을
추출하고 `animation.rows`의 상태 이름·`durations_ms`·FPS·loop를 보존합니다.
시간 배열이 없는 이전 manifest만 FPS로 균등 시간을 계산합니다.

PNG 최대 12MB/16메가픽셀, manifest 최대 2MB, 한 번에 최대 256프레임입니다.
범위 밖 좌표·프레임 수 불일치·잘못된 시간은 가져오기 전에 거부합니다.
새 자산을 만들므로 원본 run을 변경하지 않으며 유료 생성을 호출하지 않습니다.

**작업 ZIP + 후보** 탭에서는 완성된 run 폴더를 압축한 ZIP을 가져옵니다.
`manifest.json`, PNG 시트, `sprite-request.json`, `frames/frames-manifest.json`과
목록에 있는 프레임 PNG가 필요합니다. 재생 목록은 구워진 아틀라스를 그대로 사용하고,
모든 추출 프레임을 별도 후보로 보관합니다. 이미 선택된 프레임의 추출본도 후보에 포함될 수 있습니다.
후보 시간 배열이 없으면 해당 상태의 원본 request FPS를 사용합니다.

원본 ZIP은 작업 내역의 **가져온 원본 ZIP 받기**로 다시 받을 수 있습니다.
프로젝트 파일에는 재생·후보 PNG와 설정이 포함되지만 원본 ZIP 자체는 별도 백업해야 합니다.
ZIP 최대 12MiB, 확장 기준 64MiB/2048항목, 재생+후보 합계 최대 256프레임을 지원합니다.
하나의 runtime manifest만 포함해야 하며 암호화·심볼릭 링크·store/deflate 외 압축은 거부합니다.
ZIP은 디스크에 풀거나 코드를 실행하지 않습니다. curation 효과를 새로 계산하지 않으므로
가져오기 전에 sprite-gen에서 최신 편집을 compose한 완성된 작업을 사용하세요.

프로젝트 형식은 버전 2입니다. `clips[].frames[]`가 자산 참조와 `durationMs`를 소유합니다.
기존 버전 1 파일도 열 수 있으며 단일 sequence의 순서와 FPS를 첫 클립으로 변환합니다.
버전 2 파일을 이전 앱 버전에서 여는 것은 지원하지 않습니다.

## 오토타일

Map의 레이어별 설정 버튼에서 오토타일을 켜고 기본 타일·3×3 이웃 규칙을 지정합니다.
각 칸은 있음/없음/무관이며, 위쪽 규칙부터 먼저 일치하는 타일을 사용합니다.
해당 레이어의 타일 유무만 판단하므로 다른 레이어의 객체가 규칙을 바꾸지 않습니다.
사용하는 PNG는 맵 타일 크기와 정확히 같아야 합니다. 레이어당 최대 32개 규칙을 지원합니다.

원래 배치한 자산은 보존하고 표시할 타일만 계산합니다. 규칙을 끄면 원래 자산으로 돌아가며,
규칙 적용·변경은 undo/redo할 수 있습니다. 화면과 PNG 내보내기는 같은 계산 결과를 사용합니다.
프로젝트 내보내기에는 규칙과 참조 자산이 포함됩니다. 타일 아트의 시각적 이음새까지
자동으로 생성·보정하는 기능이나 가중치 랜덤 variant는 아직 지원하지 않습니다.

현재 제한: 여러 애니메이션 상태/방향의 일괄 생성,
미완성 raw-only run 재처리, 외부 curation 변형의 재편집, 선택 영역 AI 편집,
엔진별 native export는 후속 작업입니다.
실제 계정으로 유료 생성 테스트는 자동으로 실행하지 않습니다.

## 검증

```sh
npm run build
npm test
npm run test:api
cargo test --locked --manifest-path vendor/pixel-snapper/Cargo.toml
```

UI는 빈 상태와 가져온 실제 PNG 모두에서 확인합니다. 샘플 생성 이미지는 저장소에
자동으로 게시하지 않습니다. 라이선스와 고정 버전은 THIRD_PARTY_NOTICES.md를 참고하세요.
