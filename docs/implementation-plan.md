# Sprite Editor 구현 계획

Sprite Fusion의 Sprite/Map 작업 흐름, Pixel Snapper의 픽셀 정규화,
sprite-gen의 생성·추출·후보 편집을 공용 자산과 프로젝트 안에서 연결한다.
초기 분석의 네 단계와 완료 조건을 유지하며, 일부 기능의 통과를 전체 완료로 대신하지 않는다.

## 단계별 범위

| 단계 | 범위 | 완료 조건 | 현재 상태 |
| --- | --- | --- | --- |
| 1. 자산 생성·보정 | run 가져오기, 생성 연결, 후보 선택, 픽셀 편집, 처리 비교, PNG/atlas 출력 | 채택 revision과 출력 픽셀·크기·알파 일치 | 기본 경로 구현. 실제 provider 품질과 미완성 run 재처리 검증은 남음 |
| 2. 애니메이션 | 상태·방향·후보 pool·timeline·피벗·재생 검수 | 채택 순서·개별 duration·정렬이 manifest 및 preview에 일치 | 클립·후보·방향별 모션·피벗/위치 정렬과 출력 왕복 구현. 다중 상태 요청·외부 curation 변형 재편집은 남음 |
| 3. 맵 통합 | 타일셋, Tile/Object 레이어, 브러시·채우기·선택, 충돌, 생성 자산 바로 배치 | 생성→채택→맵 확인→재편집→출력 왕복 | 개별 자산·오토타일·객체 편집 구현. 타일셋 시트 선택과 실제 생성에서 시작하는 전체 왕복은 남음 |
| 4. terrain/scene 확장 | autotile, 이음새 검사, 반복 배경, shadow, parallax, 엔진별 출력 | 이웃 규칙·시각 이음새·pixel/painted 렌더 정책 검증 | 3×3 이웃 규칙 구현. 이음새 검사·배경·shadow/parallax·엔진별 출력은 남음 |

## 공통 계약

- 생성 및 수정은 입력 revision을 보존하고 새 자산을 만든다. 사용자가 채택한 참조만 바꾼다.
- 타일은 이산 격자 좌표, 객체는 픽셀 좌표와 피벗을 쓴다. 원본 비율을 유지한다.
- 맵의 표시·선택·PNG 출력은 같은 배치 순서와 좌표 계산을 쓴다.
- 프레임의 시간·순서·위치·피벗·variant·후보와 자산의 부모 관계는 전체 프로젝트 백업에 포함한다.
- 선택 영역 AI 편집을 구현할 때 마스크 밖 픽셀은 원본으로 재합성해 보존한다.
- 제공자 실행은 요청 시점 자산과 설정을 기록한다. 실패·취소 후 유료 요청을 자동 반복하지 않는다.
- 실제 provider 결과의 자연스러움·방향·정체성 검수는 로컬 fixture 검사와 별도로 기록한다.

## 최근 완료 단위: 애니메이션 정렬과 피벗

- 공통 셀의 피벗과 프레임별 정수 이동량을 원본 이미지와 분리해 저장한다.
  이동으로 넘친 부분은 여백으로 보존하며 미리보기와 출력이 같은 배치 계산을 쓴다.
- 정렬 초안, 취소, undo/redo, 이전 프레임 겹쳐 보기, 후보 보관/복원과 프로젝트 저장을 연결했다.
- 아틀라스 v2는 출력 셀·피벗과 원본 영역·편집 이동량을 함께 기록한다.
  가져오기는 원본 크기로 복원하며 재출력할 때 보정을 이중 적용하지 않는다. v1 읽기도 유지한다.
- 공용 fixture로 프런트엔드 출력과 Python 입력 계약, 잘못된 좌표·피벗·메모리 상한을 검사했다.
- 실제 다운로드 PNG 381×176의 전체 RGBA가 독립 합성과 일치했다. 이 PNG/JSON을 실제
  API로 가져와 원본 크기/픽셀·개별 시간·피벗·이동량과 재출력 manifest의 동일성을 확인했다.
- 데스크톱·모바일에서 정렬 입력, 취소/undo/redo, 후보 복원, 한 번 재생 종료와 새로고침 복원을 확인했다.
  파일 선택창을 포함한 가져오기 전체 UI 경로와 실제 provider 품질은 이번 검증에 포함하지 않았다.

## 이전 완료 단위: 객체 레이어

- 프로젝트 v3에 `layers[].kind`와 `objects[]`를 추가했다. v1/v2를 열 때 기존 격자 배치를 보존한다.
- 자유 배치·드래그·격자 스냅, 피벗·겹침 순서·충돌 입력, 자산 교체와 Sprite 편집 진입을 연결했다.
- 타일과 객체가 용량 상한을 공유하며, 타입이 다른 레이어에 잘못 저장된 배치는 가져오기에서 거부한다.
- 화면과 PNG가 공용 배치 계산을 사용하고, PNG 출력은 참조 이미지가 모두 준비된 뒤 진행한다.
- 회귀 검사는 이전 형식 복원, 픽셀 좌표·z 순서, 숨김 레이어, 용량, 잘못된 참조·피벗,
  객체만 참조하는 자산의 백업 및 ID 재매핑을 포함한다.
- 실제 브라우저에서 이동/undo/redo, 피벗·버전 교체, 더블클릭→픽셀 수정→새 revision 채택,
  프로젝트 재시작 복원, 데스크톱·모바일 입력을 확인했다. PNG 전체 RGBA와 독립 합성이 일치했다.
- 다운로드한 프로젝트를 실제 검증·PNG 가져오기·ID 재매핑 함수로 별도 저장소에 복원했다.
  네이티브 파일 선택창을 포함한 프로젝트 열기 전체 UI 경로는 이번 단위에서 미실행이다.

## 다음 작업 순서

1. 다중 상태 요청과 후보 변형, 미완성 run의 비파괴 복구.
2. 타일셋 시트 선택과 지형 이음새 검수.
3. 반복 배경·그림자·parallax 및 렌더 정책.
4. 엔진별 export와 각 소비자의 실제 가져오기 검증.
5. 실제 생성 결과를 사용한 전체 흐름 및 품질 검수. 실행 허가와 제공자 이용 가능 상태가 필요하다.

기능 단위마다 관련 검증을 통과한 뒤 커밋하고 푸시한다. 배포와 유료 생성 실행은
각각의 기존 허가 범위를 확인한다. 위 미완료 항목이 남아 있는 동안 전체 완료로 표시하지 않는다.
