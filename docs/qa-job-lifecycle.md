# 작업 취소·실패 검증 — 2026-09-13

## 재현과 수정
이전 HEAD의 Jobs 구현을 별도 로컬 모듈로 실행했다. 종료 신호를 무시하는 stand-in을
취소한 후 상태는 cancelled였지만 뒤의 작업은 queued에 남았다. 기존 wait는 최대
1200초이므로 한 번 보낸 SIGTERM에 응답하지 않는 실행 파일이 worker를 붙잡았다.

수정은 짧은 간격으로 취소 이벤트를 확인하고, 취소/timeout에서 프로세스 그룹 전체에
종료 신호→유예→강제 종료를 적용한다. 취소 요청 API는 유예 시간이 끝나기를 기다리지 않는다.
취소 결과는 PNG가 이미 만들어져 있어도 자산으로 게시하지 않는다.

서버는 포트를 먼저 확보한 뒤 job 복구를 수행한다. 중복 실행이 포트 충돌로 실패하기 전에
기존 서버의 running job을 failed로 바꾸지 않는다. 정상 SIGTERM/Ctrl+C 종료에서는
진행·대기 작업 취소와 worker 정리를 수행한다. SIGKILL 같은 복구 불가능한 종료 및
외부 제공자의 원격 실행/과금 취소까지 보장하지 않는다.

## 실행 검사
- 실제 로컬 실행 파일과 자식 프로세스가 SIGTERM을 무시하도록 구성.
- 취소 API 반환, 다음 작업 완료, 취소 PNG 미게시, 자식 heartbeat 정지 확인.
- 대기 작업 취소 시 실행 폴더도 생성하지 않음.
- timeout 후 failure 보존과 다음 작업 진행 확인.
- 실패 exit, 유효하지 않은 PNG, spawn 오류 후 worker 생존 확인.
- 종료 시 진행·대기 취소, 종료 후 새 submit 거부 확인.
- 프롬프트 선행 공백 때문에 생성 후 자산 이름이 비는 경로 방지.
- 미지원 필드/잘못된 provider/자산 ID/실수형 크기는 실행 전에 거부.
- 포트 충돌 시 Store/Jobs 초기화가 호출되지 않음.

Python 전체 18개 통과. 외부 이미지 생성 호출, 사용자 자산 변경, UI 변경은 없었다.
